---
'baseline-kit': minor
---

`Box` and `Padder` text lands on the row baseline in a flex or grid row aligned on `baseline` or `last baseline`, in Chromium, Firefox and WebKit (tested with Playwright's Chromium 153, Firefox 155 and WebKit 26.6, React and Remix). Before, Firefox and WebKit read an empty padding track and lined a Box up with a box edge, and a Padder drawing spacers (the default, and a Box with a `className`, `style` or `width`) lined up with a padding edge in every engine.

- A Box, and a Padder with a content host (one drawing spacers, or inside a Box), lays out its grid in one row: the content, with the block padding as its margins. That includes a Box with `debugging="none"` and a `className`, `style` or `width`, whose inner `bk-pad-plain` Padder used to carry the block padding as CSS padding. Spacers paint the padding out of flow. Sizes and positions match 7.1.2's for each variant tested (overflowing fixed heights included), except as noted below.
- Not covered: a `Padder` used directly with `debugging="none"` keeps its three-row grid and CSS padding, and still misreads its last baseline in Firefox and WebKit. Table cells, vertical writing modes, right-to-left text, fractional or rem paddings, and browser zoom other than CSS `zoom` are not tested.
- `baseline-kit/core`: `createBoxDescriptor` returns the block padding as `contentStyle` (margins) and keeps only the columns in `spacingStyle`; `createPadderDescriptor` takes an optional `contentHost` and returns `contentStyle` and `sideStyle`, and with spacers its `containerStyle` carries `gridTemplateColumns`. Padders with a content host carry `bk-pad-hosted`. If you render markup from these descriptors, apply `contentStyle` to the content element, or the block padding is lost, and `sideStyle` to the left and right spacer wrappers, or they cover the corners.
- Remove a workaround for this issue that adds an element to the first grid row (such as `.bk-box__grid::before { grid-row: 1 }`): that row is now the content, so the workaround moves the baseline instead of fixing it. CSS that sets `grid-template-rows`, or places items or pseudo-elements by row line, on `.bk-box`, `.bk-box__grid` or a `.bk-pad-hosted` Padder changes meaning the same way.
- With a content host, transitions on the Box host, `.bk-box__grid`, `.bk-pad` or `.bk-spr` no longer animate the block padding; put one on `.bk-pad-content` (`margin-block`).
- Block margins on `.bk-pad-content` are replaced while there is block padding, and count as snap padding when there is none. The spacer wrappers (`.bk-pad-top`, `-left`, `-right`, `-bottom`) are out of flow and transparent to the pointer, so sizes set on them no longer affect layout, and they, their Spacers and any `indicatorNode` content no longer receive pointer events; content reaching into the padding, such as a first-line button, takes them instead.
- Visible spacer bands paint over text that reaches into the padding, as the Box's padding bands do. With `indicatorNode`, a Padder whose content is shorter than a line keeps its hidden-mode size instead of growing by the indicator's line. `row-gap` on a Box, or on a Padder with a content host, no longer adds height. A negative block padding now applies as a negative margin; 7.1.2 dropped the whole track list.
